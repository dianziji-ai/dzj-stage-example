# 官方例子卡：从分区到画面，一步一步

例子的代码是照着卡 `dzj-stage-example`（「电子姬的同居日常」，网站上 `/chat/dzj-stage-example`；卡 id 是 `ca44070d`，素材地址里用的是它）写的：**分区 id、存档字段都和这张卡一一对应**。所以拿自己的卡直接 `npm run dev`，代码读不到这些分区，对话框会是空的、存档也存不进去。

这一篇按「数据从哪来 → 怎么变成画面」的顺序把例子讲一遍。做自己的游戏时，照着同样的顺序改：先定分区，再写解析，最后画界面。

## 0. 整体思路：让 AI 写「事实」，让舞台决定「画面」

舞台卡最容易踩的坑，是让 AI 去管画面：「这句用第 37 号立绘」「背景换成 bg_cafe_night.webp」。模型记不住编号，聊得越久越乱。

例子的做法反过来：

| AI 只写这些事实 | 舞台负责 |
|---|---|
| 这句话她是什么表情、在做什么（害羞、握着手柄） | 去配图库挑哪张立绘、名牌换什么颜色 |
| 现在在哪、几点、穿什么（cafe、周五 19:15、外出服） | 去配图库挑背景、换衣服、顶栏写什么 |
| 好感变了多少（+3） | 累计、夹范围、存档 |
| 剧情走到了哪一幕（回忆 3） | 解锁、弹全屏 CG |

AI 写错了（表情写成「脸红」、地点写成「火星」），舞台**宽容地认回来或者原样不动**，画面永远不会坏。下面每一步都是这个思路。

★而且「事实 → 哪张图」这张对照表**不写在舞台代码里，写在卡的配图库里**（第 3 节）：作者加一套衣服、加个动作、给某地补夜景，只改配图库，不用改代码、不用重新上传舞台。

## 1. 分区：卡里定义 AI 每轮写哪几块

在网站编辑器「分区」页建这 7 个区（区 id 必须一样；老卡还留着一个关掉的 `talk` 对话区，见下面「剧本式正文」）。每个区的完整说明（instruction）和 AI 写法（schema）在 `src/game/__fixtures__/card.json` 的 `slots` 里，照抄过去即可。

| 区 id | 类型 | 显示名 | AI 写什么 | 舞台怎么用 |
|---|---|---|---|---|
| `scene` | yaml | 场景 | 地点（6 个英文 id 之一）/ 时间 / 天气 / 穿着 | 换背景（地点 + 时段）、换衣服、顶栏（`useZoneData('scene', HOLD)`） |
| `narrative` | yaml（列表，`role: content`） | 正文 | **剧本式**：旁白和台词按发生的先后排成一列，一条一句：`谁: 旁白 / 电子姬 / 我 / 消息`，她的条目带 `表情 / 动作`；一条旁白 → 1～4 条台词交替 | 照顺序一句一句播（`beats.ts`），她的每句自带表情 → 换立绘 |
| `thought` | markdown | 心声 | 每轮一句她没说出口的话，20 字以内（`role: content`） | 整轮飘在立绘旁（`useThought`），不进对话框 |
| `status` | yaml | 状态 | 只写**变化**：`好感变化: 3`、`心情: 害羞`、`天数变化: 1` | `onTurn` 结算进存档（`logic.ts` 的 `nextSave`） |
| `cg` | markdown | 回忆 | 剧情到了特别时刻，只写一个编号（`3`） | 解锁、全屏弹出（`imageUrl` 按编号取图） |
| `game` | yaml | 小游戏 | 想请玩家抓娃娃时：`硬币: 2` | 结算进存档 |
| `action` | — | 选项 | 3 条行动；能换地方时第 4 条写 `【前往：cafe】一句话` | 选项按钮；换场那条单独做成带目的地缩略图的「门」 |

`HOLD`＝`{ hold: true, complete: true }`：这一轮还没写到就用上一次的、写完才换（见 [sdk-react.md](sdk-react.md#按分区订阅)）。场景这种「一直该有个值」的区用它；**只写变化量的区（状态）别加 hold**，不然会一直显示上一轮的变化。

分区页里每个区的几个字段：

| 字段 | 是什么 |
|---|---|
| `kind` | `yaml`＝数据区，AI 写「键: 值」（或 YAML 列表），SDK 解析成对象 / 数组；不写或 `markdown`＝文字区。★**选项区的 id 必须叫 `action`**：SDK 只认这个 id 是选项（`useZoneList`） |
| `role` | 正文区、心声区写了 `content`：它是这一轮的「内容」，平台不把上一轮的值回灌给 AI、也不进面板档案（每轮都是新的剧情，不该照着上一轮抄）。★yaml 列表的正文区**必须**写，不写会被当成状态回灌，模型照着抄、格式崩 |
| `instruction` | 给 AI 的说明：这一区写什么、什么时候写 |
| `schema` | AI 写法的骨架。YAML 列表的续行缩进 2 格，说明整个包在【】里 |

★心声为什么单独一个区：早先写成旁白里的 `> 💭` 引用块，「用得上才写」的可选格式模型最容易忽略（舞台卡柳月儿实测：改造后 500 轮一条都没写）。单独成区以后，AI 每轮都按区填，舞台直接 `useZoneText('thought')` 读，对话模式里也是独立一块、皮肤能单独做成气泡。

★为什么台词要写成数据：台词混在散文里，模型每轮写多少句、谁说的、什么表情，全靠舞台去猜（引号里是不是台词？这句是谁的？）。写成列表的条目以后，**一句话是谁说的、什么表情，AI 直接写成数据**，舞台不用猜，一句一换立绘也就有了依据。

★为什么旁白和台词在**同一个**列表里（剧本式正文，2026-10-10 起）：以前旁白一个区、台词一个区，界面只能先播完整轮旁白、再播全部台词——换场时最明显，人已经到了新地方，上一个地方的话才开始说。排在一个列表里，AI 按发生的先后写，界面照顺序播就对了。完整说明（区怎么定义、规则怎么写、老消息怎么办、对话皮肤怎么写）见 [script-narrative.md](script-narrative.md)。

## 2. 一轮怎么拆成一句一句（`src/game/beats.ts`）

对话框是 galgame 式的：点一下看下一句。`turnBeats(这一轮的原文, 玩家这轮说的话, 是否还在生成)` 把一轮拆成 `Beat[]`：

```ts
type Beat =
  | { kind: 'you'; text: string }                                  // 你说的（「我」的条目）
  | { kind: 'narr'; text: string }                                 // 旁白一条
  | { kind: 'note'; source: string; text: string }                 // 屏幕消息（「消息」的条目，source＝来自）
  | { kind: 'her'; text: string; say: boolean; look: Look }         // 她的一句，自带样子（表情、动作的原文）
```

规则：

1. **照列表的顺序**：AI 写的就是发生的先后，一条一句。
2. `谁` 是 `旁白` / `消息` 的照原样；写了、又不是她＝你（模型偶尔写成玩家的名字）；没写 `谁` 的算她。动作和台词都空的跳过。
3. **从这一轮的原文读**（`useGame.ts` 的 `useBeats`：生成中＝正在长的原文，回看＝那一条），不依赖卡上现在开着哪个区——老消息（旁白区散文 + 对话区）照旧能读：先旁白、后对话。
4. 列表用容错拆法（`scriptRows`）：同一条写了两次同一个键以后写的为准、值被换行打断不丢字。严格 YAML 一出错整区就一句都没有。
5. 生成中只给**写完的条目**（最后一条可能还在写），而且只增不减（`keepGrowing`）：界面不跟着半截解析抖。
6. 玩家原话**不插进句子列表**：你刚说完、回复还没写出第一句时，对话框显示你说的这句；回复第一句一到就翻过去（`Dialogue.tsx` 的 `waiting`）。以前把它塞成第 0 句，模型写出「我」的条目时又撤掉＝整列前移，画面在跳。

## 3. 立绘和背景怎么挑：配图库当对照表（`src/game/art.ts` + SDK 的 `pickImage`）

★这一节是例子最想教的东西：**挑图规则写在卡的配图库里，不写在代码里。**

### 3.1 配图库怎么配

网站编辑器「配图库」里，每张图可以进好几个组。组名用 `/` 分段：第一段是**类别**，后面每段是一个**标签**；标签可以带**键**（`键=`），`|` 后面是**近义词**。这张卡现在是这样：

| 组名 | 里面的图 | 意思 |
|---|---|---|
| `立绘/谁=电子姬` | 她的全部 27 张立绘 | 这些是电子姬 |
| `立绘/穿着=卫衣\|小鸡卫衣\|连帽衫` | 小鸡卫衣那 10 张 | 穿卫衣（AI 写「连帽衫」也认） |
| `立绘/穿着=睡衣\|睡裙\|家居服…` / `立绘/穿着=外出服\|连衣裙…` | 各 8～9 张 | 另外两套衣服 |
| `立绘/表情=害羞\|羞\|脸红\|紧张…` | 每套衣服里害羞那张 | 8 种表情各一个组 |
| `立绘/动作=打游戏\|游戏\|手柄…` | 握着手柄的 2 张 | 她在打游戏 |
| `立绘/动作=睡着\|睡觉\|打瞌睡…` | 抱着小鸡打瞌睡那张 | 她睡着了 |
| `立绘/默认` | 小鸡卫衣 8 张 | 没写穿着、又没有上一张时穿它 |
| `背景/地点=home\|房间\|主人的房间` | 房间的白天、晚上两张 | 地点 |
| `背景/时段=白天\|早上\|上午…` / `背景/时段=晚上\|傍晚\|深夜…` | 房间的白天 / 晚上 | 只有房间分了时段，别的地点一张通用 |
| `地图` | 大地图 | |
| `娃娃/名字=小黄鸡\|chick` … | 每只娃娃一张（6 个组） | 抓娃娃机和图册里的娃娃（按名字挑） |

这些组的画廊闸门都设 **-1**（不公开：玩家的图册里看不到，编辑器里照常看得见、能改）。平台不会把配图库给 AI 看，放多少图都不占提示词。

### 3.2 舞台怎么挑

AI 每句写的事实，按重要性排好交给 `pickImage`（`art.ts` 的 `spriteOf`）：

```ts
pickImage(snap, '立绘', [
  { value: '电子姬', key: '谁', must: true },   // 必须对上
  { value: 动作原文, key: '动作' },              // 「紧紧握着手柄」里包含「手柄」就算
  { value: 场景区的穿着, key: '穿着' },
  { value: 表情, key: '表情' },
], { seed: 这句话, prev: 上一张 })
```

每张图、每个维度看「对得多准」：**正好是标签名 > 正好是近义词（越靠前越好）> 原文里包含标签或近义词（包含得越长越准，所以「不开心」认成委屈而不是开心）> 对不上**。逐张比：

1. 重要的维度先比（动作 > 穿着 > 表情：握着手柄的那张只有卫衣版，穿着睡衣打游戏也挑它）；
2. 一样 → 和**上一张**共有的标签多的（没写穿着、穿着认不出时，留在同一套衣服里）；
3. 一样 → 在「默认」组里的；
4. 一样 → 多余的标签少的（没写动作时，不挑握着手柄那张）；
5. 还一样 → 按 `seed`（这句话的原文）固定挑一张：同一句回看永远是同一张。

`must` 的维度写了却哪张都对不上（谁＝路人）→ 返回 `null`，App 沿用上一张，画面不会空。

带键很重要：动作是一句自由文本（「开心地转了个圈」），不带键的话「开心」会被当成动作对上。

背景同理：`pickImage(snap, '背景', [{ value: 地点, key: '地点', must: true }, { value: 白天/晚上, key: '时段' }])`（`bgOf`），场景区的「周五 19:15」先换算成白天 / 晚上（`periodOf`）。

### 3.3 一句一句换

`lookAt(beats, 第几句, 兜底)` 决定第几句她是什么样子：

- 这句是她说的 → 就是这句；
- 往前找她最近一句——旁白、你说话的时候她还在画面里，立绘不消失、不乱跳；
- 往前没有（一轮开头先是几句旁白）→ 往后找她第一句，**提前换好**；
- 这一轮她一句都没说 → 上一轮最后的样子。

对话框每换一句，把她的样子交给 App（`onFocus`），App 用 `spriteOf` 挑图交给 `Scene`。`Scene` 用 SDK 的 `CrossfadeImage`：新图下载解码完才淡入，透明底立绘交叉淡化不重影。

### 3.4 换成你的卡

- 立绘多（多角色、多套衣服、多种姿势）：一样的写法。多角色就多几个 `立绘/谁=某某` 组，dims 里 `谁` 用对话区写的名字。
- 规则复杂也不用写代码：替补顺序写进近义词。比如性爱组只有「迷离」那张，就把组名写成 `表情=迷离|害羞|哭泣`——AI 写害羞时，有真正标着害羞的图先用它，没有才退到迷离。
- 技术验证：舞台卡「柳月儿」原来手写了 200 多行挑图逻辑（153 张立绘，穿着 × 行为 × 表情，近义词表 + 组内替补表），全部改成配图库的 50 个组后，拿 4442 句真实回复对照，99.3% 挑出同一种图。

## 4. 一轮写完：结算进存档（`src/game/logic.ts` + `rules.ts`）

`rules.onTurn` 在 AI 这一轮写完、玩家在场时调一次，按这轮的分区算新存档：

- 好感：`好感变化` 是加减量，每轮夹到 ±5、总数夹到 0–100（**规则在舞台，不靠 AI 自觉**）；
- 地点：场景区的地点 id 认得出才换；
- 回忆：cg 区的编号，没解锁过的解锁；
- 硬币：game 区的硬币，每轮最多 3 枚。

AI 看不到存档。每句话发出去之前，用 `withState(话, stateForAi(存档))` 在末尾附上「此刻状态」（当前好感、地点、已解锁的回忆……），AI 据此写剧情、判断 CG 时机；它只写变化。详见 [state.md](state.md)。

## 5. 选项和换场（`src/game/Choices.tsx`）

选项区每轮 3 条：一条顺着走、一条追问试探、一条撒娇逗她。

能自然换个地方时，AI 加第 4 条：`【前往：rooftop】天台能看到整座城的夜景，带她上去看看`。`travelOf()` 认出来以后单独做成一扇「门」：左边是目的地那张背景、写着「换场 · 星空天台」，点了只发后面那句话。地点不在地图里的（`【前往：火星】`），整条丢掉，不把标记露给玩家。

地图页（`MapPage`）是另一个入口：点地点直接替玩家说「（和电子姬一起去 X）」。

## 6. 快捷指令（`src/game/ShortcutTray.tsx`）

快捷指令**不写在舞台里**，配在卡上（网站编辑器「快捷指令」）。舞台用 `useShortcuts()` 从快照的 `shortcuts` 读，对话模式用的也是同一份，作者改一处两边都变。

- 卡上一条都没配：⚡ 按钮不出现。
- 每条有个 `mode`：`fill`（缺省）填进输入框等玩家改完再发，手机上顺手打开全屏输入；`send` 点了直接发。
- 例子卡配了 8 条：前 7 条是 `fill`（打游戏、去各个地点、跳时间），最后一条「摸摸头」是 `send`，芯片上标「直发」。

同理，背景音乐（`snap.bgm`）、角色包（`snap.characters`）、封面和背景图（`snap.card`）也一律从快照读，见 [bridge.md](bridge.md#卡上有的一律从快照读)。

## 存档结构

仓库里的 `src/game/state.schema.json` 就是这张卡的存档结构（字段：`location` 地点、`unlockedCg` 已解锁的回忆、`day` 天数、`love` 好感、`mood` 心情、`claw` 抓娃娃）。把它整份粘进你的卡：编辑器「舞台 → ② 存档结构」保存。`logic.test.ts` 里有一条测试保证它和代码里的 `DEFAULT_SAVE` 对得上。

## 开场

`src/game/__fixtures__/card.json` 的 `opening` 是这张卡的开场原文（场景 + 旁白 + 4 句对话 + 第 1 张回忆 + 选项，含一条换场）：把它填进编辑器「开场」页。

## 素材

立绘、背景、地图、抓娃娃机的娃娃（`娃娃/名字=小黄鸡|chick` 这类组，`claw/data.ts` 的 `plushUrl`）、回忆 CG 都在卡的配图库里；`src/game/manifest.json` 只剩配图库管不到的视频（开场视频、彩蛋视频），指向官方卡的素材库。做自己的卡时，把图传到自己卡的配图库、视频传到素材库，换掉这份清单里的地址。回忆 CG 要在编辑器「素材库 → 相册」里按编号 1–8 配好（`imageUrl` 按编号取）。

视频也在这份清单里：`film` 是舞台开场视频（新开一局进游戏前放一次，可跳过），`eggs` 是图册里一直开放的彩蛋视频。每段都是 `{ src: 视频地址, poster: 第一帧截图 }`，不想要就删掉这两项。播放走 SDK 的 `useTapVideo`（`src/game/VideoViewer.tsx`），点了才播，安卓浏览器也关得掉。

## 测试用的真实回复

`src/game/beats.test.ts`、`logic.test.ts` 用 `__fixtures__/card.json` 里的真实开场做测试，覆盖拆句、认表情、选立绘、换场、结算。想用自己卡的回复做测试：本地开发打开舞台 → 切到对话模式（或网站工具栏的「记录」）→ 找到那条 AI 回复，复制原文，存成 fixture。
