# 剧本式正文：旁白和台词写在一个列表里

舞台卡的正文推荐这样写：**一个分区、一个 YAML 列表，旁白和台词按发生的先后排在一起，一条一句。** 官方例子（电子姬）和柳月儿两张舞台卡都是这样（2026-10-10 起）。

## 为什么

以前常见的写法是两个区：旁白区（散文）+ 对话区（台词列表）。界面只能「先播完整轮旁白、再播全部台词」：

- 换场时最明显：旁白已经写到了新地方，上一个地方的话才开始说，时间线倒回去了；
- 一轮读起来是「一大段描写 + 一串对话」，不像 galgame。

写在一个列表里，AI 按发生的先后写，舞台照顺序播，顺序天然就对。

## 分区怎么定义

| 字段 | 写什么 |
|---|---|
| 区 id | **继续用 `narrative`**。平台很多地方按这个 id 认「正文」（审卡、剧情生图、开场工具…），另起一个新 id 会让这些功能找不到正文 |
| `kind` | `yaml` |
| `role` | **`content`**（必须）。不写的话平台把它当状态区，把上一轮的值回灌给 AI，模型照着抄、格式崩 |
| 对话区 | 原来的对话区（`talk`）**关掉**（别删：老消息里还有它，关掉就行） |

schema（例子卡的，照着改角色名和表情词）：

```yaml
- 谁: 【旁白 / 电子姬 / 我 / 消息 四选一】
  来自: 【只有消息的条目写：消息的来源，如「💻 电子姬 App」；其它条目不写这一行】
  表情: 【只有电子姬的条目写：平常 / 开心 / 害羞 / … 之一；其它条目不写这一行】
  动作: 【电子姬和我的条目写：说这句话时一个简短的小动作；旁白和消息的条目不写这一行】
  说: 【旁白：这一小段旁白；电子姬：她说的话，不加「」；我：只能照抄玩家原话；消息：消息内容】
```

instruction 里一定要写清的几条（完整原文见 `src/game/__fixtures__/card.json` 的 `slots`）：

1. **节奏固定**：一条旁白 → 1～4 条台词 → 一条旁白 → 1～4 条台词……交替往下写。
2. **不许连着写两条旁白；不许旁白全写在前面、台词全堆在后面。**（不写这条，模型会退回老习惯）
3. 旁白每条 2～4 句、有字数上限，只写这一小节；写完就停，接着写这一小节里说的话。
4. 换地方：先把当前地方的话说完，再写一条旁白交代怎么过去，再写新地方的台词。
5. 旁白里不写台词；「我」的条目只照抄玩家原话。
6. 每一项的值写在同一行、用单引号包起来（不要 `|` 折行）。

卡的主提示词里如果有「旁白区写…、台词写进对话区」这类话，一起改掉。

## 舞台怎么读（SDK 拆列表 + `src/game/beats.ts`）

- **舞台不自己解析原文**：列表由 SDK 拆（`useZoneRows('narrative')` / `zoneRows(zones, 'narrative')`），和网站聊天页同一套解析；舞台只把每一条变成一句（`scriptBeats`）。
- 生成中 SDK 只给写完的条目（半行不拿去解析，最后一条可能还在写也不给），条目只增不减；回看＝那一轮的列表。
- 模型写坏了（同一条写了两次同一个键、缩进塌了）：平台按卡的骨架（schema）装配救回来，所以**正文区一定要写 schema**。救不回来的，聊天页会把原文整段挂出来，舞台这一轮没有句子。
- 结算（`onTurn`）里拿到的是同一份解析好的分区：`zoneRows(zones, 'narrative')`。
- 老消息（旁白区散文 + 对话区）舞台不读：切剧本式时把老回复转掉（见下）。

## 对话皮肤怎么写

对话模式（不开舞台）的皮肤里，正文区的模块用循环：

```html
<div data-zone="narrative" class="chat">
  [[#each narrative]]<div class="msg" data-who="[[.谁]]">…[[.表情]]…[[.来自]]…[[.动作]]…[[.说]]…</div>[[/each]]
</div>
```

- ★模块里**不能出现裸的 `[[narrative]]`**：一出现，平台就把整个区当散文、不解析成列表。
- 用 `data-who` 区分样子：`[data-who="旁白"]` 画成正文段落（没有头像、名牌），`[data-who="消息"]` 画成屏幕消息。原来「表情为空＝我」这类选择器要排除旁白和消息（例子用 `.msg:not([data-who="旁白"],[data-who="消息"]):has(.face:empty)`）。
- 老消息（散文）在新皮肤里解析不成列表，平台会把原文整段挂在这一块里显示，不会丢。

## 老消息要不要转

不转也能显示（舞台、皮肤都兼容）。但**模型每轮只看最近一两条历史，历史长什么样它就学什么样**：一局里最近几条还是老格式，新一轮很可能也写成老格式。所以官方两张卡都把带对话区的老回复转成了剧本式：

- **别让 AI 重写文字**。让模型只回顺序（`N1 T1 T2 N2 …`），程序按顺序把原文拼回去，逐条核对每段原文都还在、平台能读成列表；不合格就按比例穿插。
- **别机械地「旁白全放前面」**：实测这样转完，模型新写的回复也学成旁白连写。
- 先算好、存原文备份，再批量写库，紧接着切卡的分区 / 皮肤。

这一步动的是玩家的聊天记录，作者自己做不了，需要的话找平台。
