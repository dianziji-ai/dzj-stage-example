# 存档与「此刻状态」

舞台有两份数据，别混：

| | 存档 | 此刻状态 |
|---|---|---|
| 是什么 | 舞台自己的游戏数据（好感、背包、地图、小游戏进度…） | 每次发话时附给 AI 看的当前数值 |
| 存在哪 | 平台（这一局的 `stage_state`）：`stage.save()` 请网站存（一般交给存档器） | 跟着玩家那句话一起发，`<dj_state>…</dj_state>` |
| AI 看得到吗 | **看不到** | 看得到（只看最新一份） |
| 谁定格式 | 存档结构（JSON Schema） | 舞台自己定 |

## 存档结构

★**写存档代码之前，先在网站上定义好这张卡的游戏状态**：编辑器 →「舞台」→「② 存档结构」，贴一份 JSON Schema 保存。没定义的卡不能存档（舞台读到的 `state_schema` 是 `null`，`save` 也是 `null`）。
定义好之后在网站里重新进入这一局、打开舞台（本地开发同样；结构是进来时随快照一起给的），本局面板 →「存档」页能看到结构和开局存档，就说明生效了。以后加字段、改范围，也是先改结构，再改代码。

**推荐：结构放在仓库里，和代码一起改**（官方例子就是这样）：

1. 结构写在 `src/game/state.schema.json`，和代码一起改、一起提交。
2. 改完把它整份粘进网站编辑器「舞台 → ② 存档结构」保存。
3. 例子的 `logic.test.ts` 里有一条测试：结构里各字段的 `default` 拼出来必须等于代码里的 `DEFAULT_SAVE`。只改了一边，`npm test` 就会挂。

在网站编辑器「舞台 → ② 存档结构」写一份标准 JSON Schema，根节点必须是 `"type": "object"`：

```json
{
  "type": "object",
  "properties": {
    "love":  { "type": "integer", "minimum": 0, "maximum": 100, "default": 20 },
    "place": { "type": "string", "default": "home" },
    "items": { "type": "array", "items": { "type": "string" }, "maxItems": 50, "default": [] }
  },
  "additionalProperties": false
}
```

- **开局存档**＝各字段的 `default`。还没存过、或存档不符合结构（作者改了结构），读到的就是开局存档。
- 存档必须符合结构才存得进去（网站校验）：字段、类型、取值范围不对返回 `invalid`，`message` 写明哪里不对。
- 最大 64KB。
- **不写存档结构就不能存档**（读到的 `save` 是 `null`）。会话引擎读到没有结构时自动不存，只改本地。
- 不防作弊：范围内的值玩家可以在本局面板里改。
- 支持的关键字：JSON Schema 2020-12 常用的都行（`type`、`properties`、`required`、`additionalProperties`、`enum`、`minimum` / `maximum`、`minLength` / `maxLength`、`items`、`maxItems`、`uniqueItems`、`propertyNames`…）。官方例子 `src/game/state.schema.json` 可以照抄改。

### 改了结构之后

老存档通不过新结构 → 读回来是开局存档（进度清零）。想保留进度：新字段给 `default`、别收紧已有字段的范围；实在要改，在 `normalize` 里把旧格式转成新格式。

## 每一轮怎么改存档（onTurn）

游戏规则写在 `StageBoot` / `createSession` 的 `onTurn` 里：AI 这一轮写完那一刻调一次，返回新存档。

```ts
import { zoneNum, zoneText } from '@dianziji/stage'

onTurn: ({ zones, save }) => ({
  ...save,
  love: Math.min(100, Math.max(0, save.love + (zoneNum(zones, 'status', '好感变化') ?? 0))), // 没写 → null
  mood: zoneText(zones, 'status', '心情') || save.mood,                                       // 没写 → ''
})
```

- ★AI 不一定每轮都写每一行：一律用 `zoneNum / zoneText / zoneList / zoneData` 安全取值，别直接 `zones.status.value.xxx`（一漏写就崩）。
- 只在 AI 写完那一刻算一次。玩家提前走了这一轮就不算（不补算）；存档和历史允许对不上，AI 会容错。
- `onTurn` 自己抛错：这一轮存档不变、游戏照常玩，顶部提示「这一轮的状态没算上」，控制台有原因。
- 结果在 `lastTurn`（`prev` / `next` 两份存档）：拿来做「好感 +3」「解锁新 CG」这类动效。

## 附给 AI 的「此刻状态」

存档 AI 看不到。想让它知道当前数值，发话时自己附上（附不附、附什么由舞台决定，SDK 不会自动加）：

```ts
import { withState, splitState } from '@dianziji/stage'

send(withState('我们去公园吧', { 好感: 42, 地点: '主人的房间', 已解锁的回忆: [1, 3] }))
splitState(原文).text // 显示玩家的话时把状态块藏掉
```

`withState` 把状态接在这句话后面，用平台约定的 `<dj_state>` 标签包起来：

```
我们去公园吧

<dj_state>
好感: 42
地点: 主人的房间
已解锁的回忆: [1,3]
</dj_state>
```

对象写成「键: 值」一行一个，数组 / 对象写成 JSON；也可以直接传一段字符串。

### 平台怎么处理它

它不是系统提示词，而是**跟着这一轮走的临时状态**：

| | 处理 | 结果 |
|---|---|---|
| 这一轮玩家这句话里的那份 | 去掉标签、**内容留下**，接在玩家这句话后面 | AI 看得到（当成玩家这条消息的一部分） |
| 历史里旧的那些 | **整块删掉** | AI 看不到；不会越聊越长、越来越贵 |
| 世界书扫描 | 只扫这一轮那份的**内容**（标签不算） | 状态里写了「星空天台」，关键词是「星空天台」的世界书条目就会被触发；旧状态不参与 |
| 网站聊天页、记忆摘要、聊天搜索 | 藏掉 / 剔除 | 玩家看不到，摘要也不会把它写进记忆 |
| 数据库、舞台读到的历史 | 原样（带标签） | 显示玩家的话时用 `splitState(原文).text` 藏掉 |

所以**每次带一份完整的**：没带的字段，AI 就当它不存在了。标签没闭合的平台不处理，用 `withState` 生成就不会出错。

### 什么时候用

| 场景 | 用不用 | 怎么做 |
|---|---|---|
| AI 要知道存档里的当前数值（好感、地点、天数、金币、背包、任务进度） | ✅ 用 | 每次发话都附上，键名用中文 |
| 玩家在舞台界面里做了 AI 没看见的事（小游戏的结果、买了东西、换了衣服） | ✅ 用 | 写进状态（比如「抓娃娃：玩了 3 局抓到 1 只」）；**要 AI 接着写剧情的**，再替玩家说一句话（比如「（把刚抓到的娃娃送给她）」） |
| 告诉 AI 哪些已经发生过、别重复（已解锁的回忆、已经去过的地点） | ✅ 用 | 例子：`已解锁的回忆: [1, 3]`，配合卡的分区说明「已解锁的不再写」 |
| 想在某个状态下触发世界书条目 | ✅ 用 | 把条目的关键词写进状态（地点名、角色名、阶段名） |
| 只属于这一句话的一次性结果（掷骰检定、抽卡、小游戏判定） | ✅ 用 | 只附在这一句、发完就清；卡的分区说明里写清看到它怎么处理；界面上给玩家看得见附了什么。见下面「一次性结果」 |
| 写作规则、文风、输出格式 | ❌ 别用 | 写在卡的提示词和分区说明里：那是长期规则，状态是这一轮的事实 |
| 长期记忆、剧情回顾 | ❌ 别用 | 平台有记忆摘要；状态里只放「此刻」 |
| 大段数据（完整清单、几千字的日志） | ❌ 别用 | 每一轮都算进输入、按 token 扣费：只放 AI 写剧情真正用得到的，控制在几百字以内 |
| 命令 AI 必须怎么做（「你现在必须…」） | ❌ 少用 | 它作为玩家消息的一部分出现，写成事实（「好感: 85」）比写成命令更稳 |

### 一次性结果（例：掷骰检定）

「此刻状态」每轮都带一份完整的；**一次性结果**只属于玩家这一句话——掷完骰子、抽完卡、小游戏判完胜负，结果要让 AI 照着演，但下一轮就不该再出现。`<dj_state>` 天生适合：平台只把**最后一条**玩家消息里的那份交给 AI，历史里的整块删掉，所以这一轮生效、下一轮自动消失，不用舞台去清。

三件事要一起做：

1. **舞台：只附在这一句上。** 结果先存在界面状态里，发送时拼进去，发成功就清掉：

   ```ts
   const [attached, setAttached] = useState<CheckDraft | null>(null)
   const say = async (line: string) => {
     const check = attached
     setAttached(null) // 一点发送就摘掉（send 要等整条回复写完才兑现，别等它）
     if (!(await send(check ? withState(line, checkState(check)) : line))) setAttached(check) // 发失败还回来
   }
   ```

   和「此刻状态」同时要带时，两段拼成一个字符串传进去（`withState` 只认一份）。

2. **舞台：让玩家看见附了什么。** 输入框上挂一枚小牌（「🎲 已附检定 · 敏捷 29/43 成功 ✕」），点开看详情、✕ 撤掉。玩家的话本身保持干净——AI 照抄玩家原话时也不会把这串数据抄进去。

3. **卡：写清楚看到它怎么处理。** 内容写成**带标题的事实**，卡的分区说明里认这个标题：

   ```
   【行动检定】玩家已在界面上掷骰，结果已定：
   行动: 偷看她的手机
   属性: 敏捷
   目标: 43
   掷骰: 29
   结果: 成功
   ```

   分区说明：「玩家这句话末尾附了【行动检定】时：把这几项照抄进本区，剧情按结果演，不要重掷、不要改判；本轮没有检定时整个分区不要写」。

★别把结果写进玩家的话里（「我偷看手机〖检定=…〗」）：玩家看得见一串标记，记忆摘要和搜索会收进去，AI 照抄玩家原话时也会带上。

官方例子的做法：`src/game/logic.ts` 的 `stateForAi()` 决定附什么（地点、好感、心情、天数、已解锁的回忆、抓娃娃战况），`src/game/useGame.ts` 的 `send` 每次都用 `withState` 附上；替玩家发的话（地图出发、送娃娃）也走同一个 `send`。
